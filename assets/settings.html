    Connect a phone

    Open the Yardbell app on your Android phone, tap Scan a pairing code and point it at the code. The phone signs in without the passcode. It must be on the same mesh VPN as this server.

    Each code works once, for five minutes. Get the app from the latest release.

    Phone notifications

    The Yardbell app for Android shows these while it is signed in to this server. Nothing else to install.

    Dispatch

    Open Dispatch

    Added to Dispatch's prompt for every conversation and followed before its own defaults. Use it for where your repositories live, which machine suits which work, branch naming, and anything you find yourself repeating.

    The agent that reads your messages and proposes steps, with only Yardbell's tools, and the model it runs. Each agent keeps its own model. Your approval setting and rules work the same on both. A conversation stays on the agent it started on, so a new agent applies to new conversations, while a new model applies from the next message.

    Each step shows up in the conversation as a card. When Dispatch asks, you can approve it, edit it first or reject it, and nothing runs until you approve. A change to Dispatch's memory always asks, even when this is set to go ahead, unless a rule for it says otherwise.

    Rules

    A rule decides the steps it matches instead of the setting above. Deny always wins. Otherwise the rule that names the most of step, machine and folder wins, so their order does not matter. A folder is a name from the folder list, like acme/web, or a path, and covers the folders inside it. Use * for any part of a name.

      Dispatch runs Claude Code on this machine. The agent it starts can be any of yours.

      Memory

      What Dispatch has learned to keep: where repositories live, branch naming, conventions and your corrections. It reads this at the start of every turn, apart from your instructions above, which win when the two disagree. Dispatch proposes each change as a step you approve, edit or reject, and you can change it here at any time. It is kept in memory.md, which only your account can read.

          Triggers

          A trigger starts a Dispatch conversation from one of your tasks, on a schedule or when a ticket comes your way. Its steps follow your Dispatch rules like any other conversation. Times are in this server's time zone, the time zone of the machine Yardbell runs on.

            No triggers yet.

            Counted from midnight: every 4 hours runs at 00:00, 04:00, 08:00 and so on.

            Five fields: minute, hour, day of the month, month and day of the week, where 0 and 7 are Sunday. Use numbers, *, ranges like 1-5, lists like 1,15 and steps like */15.

            Yardbell reads your open Linear tickets every 3 minutes with the API key saved as the secret linear, under MCP servers, Secrets. Separate states with commas.

            Yardbell asks the GitHub CLI gh on this machine every 3 minutes, as the account it is logged in with.

            The task gets the ticket: write {ticket}, {title}, {url}, {state} or {repo} in it where each goes, or the ticket is added at the end. One conversation per ticket, one at a time. Tickets that already match when the trigger starts watching are left alone.

            Worktree setup

            A command that runs in each new worktree Yardbell creates for a repository, before the agent starts, such as bin/setup, npm ci or cp "$YARDBELL_MAIN_CHECKOUT/.env" .. The folder is the repository's main checkout, as in the folder list or as a path, and * matches any part of a name. If the command fails or runs past its timeout, the agent starts anyway, the session shows the output, and the agent is told.

            Only commands saved here run. A repository's own script runs only when you name it here, like .yardbell/setup, because that script comes from whatever branch is checked out.

              The command runs through your login shell in the new worktree, with the main checkout's path in $YARDBELL_MAIN_CHECKOUT.

                        MCP servers for sessions

                        Claude Code sessions that Yardbell starts get these servers, in a file only your account can read on that machine. Keep tokens in the secrets below and write ${secret:NAME} where they go.

                          Machines

                          None picked means every machine.

                          Secrets

                          Tokens for the servers above, kept in secrets.yml, which only your account can read. A value is never shown again once it is saved. Refer to one as ${secret:NAME} in a header, an environment variable or a URL, for example Authorization=Bearer ${secret:linear}.

                          A secret is not set
                          Some values are written in yardbell.yml itself Move them into secrets so yardbell.yml holds none. Tick the ones that are secret. Each is read back from secrets before it leaves yardbell.yml. Older yardbell.yml.bak- copies still hold them, so delete those afterwards.
